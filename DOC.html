01 — Architecture

System Design

Four stages, one fixed contract in the middle. Anything left of handoff.py can be swapped (real KITTI data vs. synthetic scenes) without touching the grid engine; anything right of it only ever sees the sparse cell output — never raw points.

Fixed contract: generate_2_5d_grid(points, labels, spikes) — the only thing every module downstream depends on.
02 — Runtime Behavior

Per-Frame Workflow

What happens on every single frame — from raw points to a rendered dashboard. The branch in the middle is the whole point of the module: a cell only recomputes when it actually spiked this frame.

Why this matters: on a 40-frame driving sequence, only the cells under a moving pedestrian or a newly-entered pole ever recompute — everything else is served straight from cache. This is verified directly by build_moving_sequence() in synthetic_lidar_data.py and test_grid_state.py.
03 — Perception

Spiking Neural Network

spiking_model.py — three Conv1d layers, each followed by a Leaky-Integrate-and-Fire (snn.Leaky) layer with a fast-sigmoid surrogate gradient. Only neurons that cross threshold ever fire — that sparsity is the entire energy argument.

Pulsing nodes = spikes over the temporal loop (num_steps forward passes per frame), not a literal firing trace.
ARCHITECTURE

Why sparse fire → sparse compute

Each Leaky layer only forward-propagates a nonzero signal when its membrane potential crosses threshold=0.5. The grid engine's entire event-driven cache design in grid_state.py exists to exploit exactly this: silent points cost nothing downstream either.

  • beta=0.9 — membrane leak/decay factor
  • num_steps=10 — temporal integration window
  • surrogate.fast_sigmoid() — gradient for backprop through spikes
MAC vs. AC — profiler.py

Energy per operation

A dense (non-spiking) network pays a Multiply-Accumulate cost on every neuron, every step. An SNN only pays the cheap Accumulate cost — and only when a neuron actually spikes.

04 — Core Module

Variable-Resolution Grid Engine

Not a textbook 2×2 recursive quadtree — halving 50cm repeatedly never lands exactly on 5cm. Instead: a base 50cm grid, and any parent cell whose center falls within 10m gets subdivided into a fixed 10×10 array of 5cm sub-cells, aligned to one shared origin.

Alignment guarantee: a sub-cell index is always (1) parent index from the shared origin, (2) local offset within that parent's own [0, 0.5) range, (3) floor-divided by 0.05 — never an independently-computed fine-grid origin. That's what gives generate_boundary_stress_ring() a flat, seamless render at exactly r=10m.
Subdivision is decided per parent cell, by that cell's center distance — never per point — so a single cell can never end up half-subdivided.

05 — Interface

Data Contract

Fixed between the SNN and the grid engine — negotiated once, treated as external, never silently changed.
